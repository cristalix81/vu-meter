# Сборка и проверка Audio Visualizer Pro 4.3.0

Код настольной программы развивается поверх ASAR предоставленной версии
4.2.40 и опубликованной 4.2.41. Полная portable-сборка сохраняет проверенный
Electron 37.10.3 x64, DLL и исходные 123 BIN. Четыре новых авторских прибора
отрисовываются отдельными слоями Canvas2D и не требуют BIN.

Версия кода хранится в `package.json` и показывается в диагностике.
Сохранение исходного EXE не меняет его старые файловые метаданные Windows;
они могут отличаться от версии приложения. Выпуск не добавляет Authenticode.

## Автоматические проверки

Требуется Node.js 22.15 или новее:

```sh
npm run check
npm test
```

Эти команды не устанавливают Electron и не требуют аудиоустройств. Они не
заменяют аппаратные испытания Windows, драйверов, сна, мониторов и установки.
Результаты Chromium/Canvas-проверок и реальные Windows-проверки записывайте
отдельно, с явным указанием выполненных и невыполненных сценариев.

## Воспроизводимая упаковка ASAR

```sh
node tools/pack_asar.cjs pack . /путь/к/выходу/app.asar
node tools/pack_asar.cjs verify /путь/к/выходу/app.asar
```

Упаковщик не требует npm-пакетов. Он включает корневые JS/HTML/CSS,
`package.json` и `assets`, в том числе `atelier-meter.js` и
`atelier-experience.js/.css`. Тесты, инструменты, профили, BIN, `node_modules`
и выходные каталоги исключены. Порядок файлов стабилен; каждый файл и блок
имеют SHA-256. Проверяются roundtrip, Unicode, пустые файлы, большие блоки,
повреждение и границы данных. Повторная упаковка одинаковых исходников даёт
одинаковый ASAR; дата выпуска в отдельном манифесте при этом может отличаться.

## Полный portable из проверенной базы

```sh
node tools/build-portable.cjs --base "C:\AVPro-4.2.41" --out "C:\AVPro-release-4.3.0"
```

В `--base` укажите папку, содержащую EXE, DLL, `resources` и `Skins`.
Поддерживаются точные исходные ASAR версий 4.2.40 и опубликованной 4.2.41;
проверяются не только номер версии, но и SHA-256. Также проверяются PE x64,
Electron 37.10.3, состояние встроенной проверки ASAR, комплектность runtime,
локализации и наличие не менее 123 BIN. Исходный каталог не изменяется.
Выходной каталог должен находиться вне базы и исходников.

Создаются полная папка `AudioVisualizerPro-Desktop-VU-4.3.0` и маленькое
обновление `AudioVisualizerPro-Update-4.3.0`. Только полная папка содержит
EXE, DLL и скины. Для неё предыдущая установленная версия не нужна.
Опция `--update-only` создаёт только обновление.

В полном portable заменяются ASAR, текущие README и манифест. Старый
`VALIDATION_REPORT.json` из базы удаляется, поскольку относится к прошлому
выпуску. Перед ZIP добавьте актуальный отчёт проверок, заново проверьте ASAR
и соответствие `newAppSha256` в обоих манифестах. Если код изменился после
сборки, обновите ASAR и оба манифеста до архивации и сборки установщика.

Малое обновление предназначено для точной базы, указанной в его манифесте.
`UPDATE_PROGRAM.cmd` запускает PowerShell, проверяет SHA-256 EXE и обоих ASAR,
сохраняет проверенную резервную копию и атомарно заменяет код на том же диске.
Пользователю не нужны Node.js/Python. Выполнение PowerShell-обновления требует
проверки на Windows; успешная сборка в Linux этого не доказывает.

## Настоящий NSIS-установщик без Wine

Из проверенной полной папки можно собрать установщик официальным `makensis`:

```sh
node tools/build-installer.cjs /путь/Portable /путь/AVPro-Setup.exe /путь/NSIS/linux/makensis
```

На Windows последним аргументом будет путь к `makensis.exe`. Версия
установщика берётся из текущего `package.json`. Инструмент создаёт EXE NSIS
с выбором каталога, записью в списке программ и деинсталлятором. Используется
установка для текущего пользователя. При удалении удаляются только
установленные файлы и собственная запись автозапуска
`AudioVisualizerProInstrument`; пользовательские данные сохраняются.

Компиляция настоящего NSIS PE возможна в Linux и не является запуском
инсталляции. Установку, обновление поверх старой версии и деинсталляцию
необходимо испытать на Windows. Без сертификата установщик не подписан.

## Полная пересборка Windows EXE

Для совместимости закреплены Electron **37.10.3** и electron-builder
**26.0.12**. Перед коммерческим выпуском отдельно оцените поддержку и
обновления runtime. Смена runtime требует повторной проверки аудиозахвата,
баллистики, устройств и графики.

На Windows с Node.js:

```powershell
npm ci
$env:AVPRO_SKINS_DIR = 'C:\AVPro-4.2.41\Skins'
npm run dist:win
```

`package-lock.json` фиксирует зависимости. Конфигурация
`tools/electron-builder.config.cjs` собирает portable и NSIS x64.
`AVPRO_SKINS_DIR` указывает на исходные BIN; без неё используется `Skins`
внутри проекта. Сами сторонние BIN не входят в архив исходников.

Для Authenticode нужен сертификат издателя или поддерживаемый сервис подписи.
`electron-builder` поддерживает `CSC_LINK` и `CSC_KEY_PASSWORD`; задавайте
их через защищённые переменные сборки. Не храните секреты в исходниках.
SHA-256 подтверждает целостность, но не заменяет подпись издателя.

## Приёмка на Windows

Отдельно проверьте и запишите результаты:

- Чистую Windows 10/11 x64, установку, обновление и удаление обычным пользователем.
- LINE IN/USB/виртуальный вход, моно/стерео, отсутствие устройства и возврат после сна.
- Сохранённый вход, явный STOP, автозапуск после входа и отсутствие незапрошенного DEMO.
- Один/два монитора, смену основного, отключение выбранного и DPI 100/150/200%.
- Размеры 800×480, Full HD и 4K; читаемость шкал, панели и отдельные каналы стрелок.
- VU/PPM на ступени, импульсах, тишине и тихой музыке; отсутствие шумового порога.
- Индивидуальные калибровки BIN, профили и управление макропультом.
- Authenticode и временную метку после реальной подписи.

Цифровые профили не объявлены сертифицированными IEC/ANSI. Эффекты стекла
и слоёв не являются заявлением физической 3D- или измерительной сертификации.
