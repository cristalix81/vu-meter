# Сборка и проверка Audio Visualizer Pro 4.2.41

Исходники извлечены из `app.asar` предоставленной portable-версии 4.2.40.
Исходная Windows-сборка и BIN-файлы сохраняются отдельно. Рабочая версия
приложения хранится в `package.json`; в исходном EXE остались более старые
метаданные FileVersion, поэтому сохранение этого EXE не меняет свойства файла.

## Проверки без установки зависимостей

Требуется Node.js 22.15 или новее:

```sh
npm run check
npm test
```

Проверка синтаксиса и тесты не устанавливают Electron и не требуют доступа
к реальным аудиоустройствам. Их успешное выполнение не означает прохождение
Windows-проверок устройств, сна, мониторов, установщика или подписи.

## Проверяемая упаковка ASAR

```sh
node tools/pack_asar.cjs pack . /путь/к/выходу/app.asar
node tools/pack_asar.cjs verify /путь/к/выходу/app.asar
```

Упаковщик не требует npm-пакетов. Он включает корневые JS/HTML/CSS, `package.json`
и каталог `assets`; исключает тесты, инструменты, локальные профили, BIN-скины,
`node_modules` и результаты сборки. Порядок файлов стабилен, каждый файл имеет
SHA-256 и контрольные суммы блоков. Тесты проверяют побайтовый roundtrip,
Unicode-имена, пустые файлы, большие блоки, повреждение и неверные границы.

## Portable из предоставленной Windows-базы

```sh
node tools/build-portable.cjs --base "C:\ИсходнаяВерсия\AudioVisualizerPro" --out "C:\AVPro-release"
```

Для создания только небольшого обновления добавьте `--update-only`.
Выходной каталог должен находиться вне исходников и исходной portable-папки.
Инструмент проверяет исходный ASAR, версию 4.2.40, архитектуру x64,
фактический runtime Electron 37.10.3 и отключённую проверку встроенного
ASAR-хеша в исходном EXE. Исполняемый файл, DLL и BIN-скины копируются
без изменения; исходный каталог не изменяется. Создаётся `RELEASE_MANIFEST.json`.

Обновление содержит `payload/app.asar`, `update-manifest.json`, `.cmd` и PowerShell.
Оно требует закрыть приложение, проверяет точную исходную и новую SHA-256,
создаёт проверенную резервную копию и выполняет замену на том же диске.
Node.js/Python на компьютере пользователя не нужны. Пользовательские настройки
и скины не удаляются. PowerShell-обновление необходимо проверить на Windows;
в Linux оно не запускалось.

## Полная пересборка Windows EXE и установщика

Для сохранения поведения исходной сборки закреплены Electron **37.10.3**
и electron-builder **26.0.12**. Перед коммерческим выпуском отдельно проверьте
поддержку и обновления безопасности закреплённого runtime. Обновление runtime
требует повторной проверки устройств, аудиобаллистики и графики.

На Windows с Node.js:

```powershell
npm install
$env:AVPRO_SKINS_DIR = 'C:\ИсходнаяВерсия\AudioVisualizerPro\Skins'
npm run dist:win
```

`tools/electron-builder.config.cjs` создаёт x64 portable и NSIS-установщик
с выбором каталога и деинсталлятором. Пользовательские данные при удалении
по умолчанию сохраняются. `AVPRO_SKINS_DIR` указывает на исходный каталог
BIN; без переменной используется `Skins` внутри проекта. Для повторяемой
производственной сборки сохраните созданный `package-lock.json` и используйте
`npm ci`. Эта конфигурация подготовлена, но EXE/NSIS в Linux не собирались.

## Подпись и приёмка перед продажей

Для Authenticode нужен настоящий сертификат издателя или поддерживаемый
сервис подписи. `electron-builder` поддерживает `CSC_LINK` и
`CSC_KEY_PASSWORD`; задавайте их через защищённые переменные сборки.
Не храните сертификаты, пароли и закрытые ключи в проекте. Без предоставленных
учётных данных подпись не создавалась и не заявляется.

На Windows отдельно выполните:

- Установку/обновление/удаление обычным пользователем и с каталогом под защитой UAC.
- Проверку Authenticode и метки времени у EXE/установщика после подписи.
- Первый запуск, явный STOP и автозапуск при входе, восстановление сохранённого входа.
- Windows 10/11, встроенный вход, USB и виртуальное устройство; отключение/возврат и сон.
- Один/два монитора, смену основного, отключение выбранного монитора, разные DPI.
- VU/PPM: ступень, импульсы, тишину, тихую музыку и сверку шкалы каждого используемого BIN.

Результаты этих действий должны быть записаны отдельно от автоматических
DSP/Canvas-тестов. Отсутствие аппаратного теста не помечается как его успех.

### Прямой NSIS без Wine

`tools/build-installer.cjs` собирает установщик из уже проверенной portable-папки
с помощью официального `makensis`. Например:

```
node tools/build-installer.cjs C:\Build\Portable C:\Build\AVPro-Setup.exe C:\NSIS\makensis.exe
```

Этот путь создаёт пользовательскую установку, удаление только установленных
файлов и запись в списке программ. Пользовательские данные сохраняются,
запись автозапуска `AudioVisualizerProInstrument` удаляется. Инсталляция и
деинсталляция требуют отдельного испытания на Windows. Сертификат цифровой
подписи отсутствует; установщик остаётся неподписанным.

`package-lock.json` фиксирует зависимости: для полной Windows-пересборки
используйте `npm ci`, затем `npm run dist:win`. При разработке исходников
подключайте BIN через импорт; для сборки задайте `AVPRO_SKINS_DIR` согласно
основной инструкции. Сами сторонние BIN не входят в исходный архив.
